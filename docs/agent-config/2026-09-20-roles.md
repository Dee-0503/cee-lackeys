## 实施方法

先核对固定版本原生创建／更新、persona 和技能工作区实现，以及原生 free 上限 10 个 Agent。当前 9 个角色未超限。由于 HTTP 创建接口会自动发加入消息并触发头像生成，本次使用项目范围维护事务，遵循既有字段与 conversation_members 插入触发器，只更新配置和空私聊入口。

`scripts/configure-cumora-agents.mjs` 提供 inspect/apply/verify：校验 owner、company、computer、套餐上限、身份归属、原始配置哈希和活跃 turn；单事务更新四个角色、新建五个角色、写入手册与私聊入口。不会操作示例 personal 租户、修改凭据或发送消息。模型和已有执行位置保持不变；新角色绑定同一个已配对 Codex Computer。

写入后对本项目 server 做一次受控重启清除进程内 persona 缓存。BYOA 自身保持 active，轮询检测配置变化后更新四个 runner、启动五个新 runner。

## 实际拓扑与限制

Web/API 服务运行在 Docker；BYOA daemon 由宿主机的 codex-pilot 用户运行，受限 Codex 通过身份绑定的 Cumora MCP CLI 操作应用。Web 在 Docker 内不表示所有 Agent 进程均在容器内，也不赋予 Agent 宿主机运维权限。

每 Agent 身份和 workspace 分离已存在；本轮角色工具边界主要是行为配置，未新增角色级完整硬 ACL。Cumora 的持久运行会话按 Agent 管理，按项目／任务的精确上下文目前靠显式任务记录、topic 和按需读取，不宣称拥有原生每项目独立线程／容器隔离。

以下能力尚未接入或未完成端到端验收，已写入每 Agent 的 capabilities 引用：

- 云端 canonical Wiki 查询与受检发布连接器。
- 原始音频长期存储、转写、原件与纪要关联流水线。
- 经验证的实时网页检索／抓取连接器；Cumora search 是会话检索。
- Cumora sandbox 到桌面／云端 Orca 的连接、项目映射和执行回执。
- 专用服务器 CLI 到外部沙箱／执行节点及授权服务器的连接。
- 权威待办产品最终选择，以及定时订阅、重试和真实通知送达；官方 iOS 自托管推送仍待支持。

产品分析、已提供文本的会议整理、资料分析和职责内协作可开始试用；角色不得把上述缺口表述为已完成的动作。

## 备份与回滚

服务器私有归档：`/home/cee/apps/cumora-pilot/agent-config/20260920.1/`，目录仅 root 可访问。

- `pre-agent-config.dump`：操作前一致性 PostgreSQL 备份；包含应用数据，不复制到本地仓库。
- `preimage.json`：被操作身份与原 workspace 快照，保留于服务器，不入 Git。
- `applied.json`：完成标记、版本与 payload 哈希。
- `config/agents/` 与 `scripts/`：配置源和维护脚本。

运行时操作包暂存于 server 容器 `/tmp/lackeys-role-config-v1/`；重建容器后应从服务器私有归档重新以应用用户解包，不要改变容器 capability 来迁就文件属主。

`scripts/rollback-cumora-agents.mjs inspect CONFIG_DIR PREIMAGE` 校验备份范围、角色／文件漂移，生成回滚检查摘要；同一输入下 `apply` 恢复四个旧角色配置，撤销其新增工作手册，将五个新角色软离职并保留聊天／历史。检测到后续配置或手册变更时拒绝自动回滚。回滚后需刷新 server persona 缓存，等待 BYOA 同步。

完整 DB 恢复仅作灾难恢复，不应用来覆盖配置后新增的正常工作数据。配置回滚使用上述限定脚本。新增角色需重新启用时走受检 rehire／重配流程，不能盲目重复 apply。
